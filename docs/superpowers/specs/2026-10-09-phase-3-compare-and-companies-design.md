### 2.2 公司条目深度

对齐叠纸样板，缺一不可：

- 公司 Markdown：概览、关键转折、资料分歧、来源
- 代表作 JSON：上线 / 停服、发行方、意义、能查到的流水
- 关键人物（查得到再写，查不到不编）
- 重大事件（融资、上市、改名、争议、里程碑）
- 每条事实至少一个来源；冲突标 `verified: false` 并写入资料分歧

## 3. 流水口径

在现有 `revenue` 条目上增加三个可选字段（旧数据不填也能过校验）：

| 字段 | 取值 | 含义 |
|---|---|---|
| `basis` | `store` / `all-platform` / `official-report` | 应用商店（如 Sensor Tower）、全平台估算、官方财报 / 公告 |
| `partial` | 布尔，默认 `false` | 该期间只覆盖部分月份（如上线当年） |
| `lowerBound` | 布尔，默认 `false` | 数字是下限（「超过 X」「至少 X」） |

`kind` 仍是 `official` | `estimate`。行业机构测算一律 `estimate`。同一产品仍不得混用年与季度。

对比页用条带粗细表示流水量级时：

- 只在**同一 `basis`** 的数字之间比粗细
- `partial` 或 `lowerBound` 为真的条带用更淡的填充，浮层写明「部分月份」或「下限」
- 没有流水的产品仍画条，用最细的默认粗细

叠纸已有流水在本期补上 `basis`（Sensor Tower 标 `store`，全平台估算标 `all-platform`）。

## 4. 对比页 `/compare`

### 4.1 布局

- 顶栏：公司多选（默认全选本期四家）。选择写入 URL：`/compare?c=happyelements,lingxi,papergames,youyi-shiguang`（id 按字母排序，可收藏、可分享）。公司 id 固定为：`papergames`、`youyi-shiguang`、`happyelements`、`lingxi`。
- 主体：横向时间轴（最早 `founded` / `released` 到今年），每家公司一条泳道。
- 泳道内：产品为圆角横条（左端 = `released`，右端 = `shutdown` 或「至今」）；事件为圆点，颜色跟公司页时间轴同一套类型色（融资 / 争议 / 里程碑等）。
- 悬停：浮层显示名称、日期、流水（若有）及口径说明；点击产品或公司名进入公司页（产品可带 hash `#works`）。
- 页头一句中文说明：这是并排年表，不是市值榜。

### 4.2 数据函数

`getCompareLanes(ds, ids: string[]): CompareLane[]`

- `CompareLane { company, products: ProductCard[], events: ChronicleEvent[] }`
- `ids` 为空则返回全部已收录公司
- 未知 id 忽略，不报错
- 产品按 `released` 排序；事件只含这些公司相关的条目

页面用 D3 比例尺 + 自绘 SVG，不引现成图表库。气质与首页 / 公司页一致（纸色、墨色、胭脂红）。

### 4.3 导航

页头「时间长河」旁增加「对比」。窄屏：泳道可横向拖动，公司名吸左。

## 5. 完整性与命名

在现有 `checkIntegrity` 上增加：

- 同一产品不得有重复 `period`
- `status === 'shutdown'` 必须有 `shutdown` 日期，有 `shutdown` 则 status 必须是 shutdown
- `shutdown` 不得早于 `released`；任职 `to` 不得早于 `from`
- 发行方若是自由文本：构建时列出本库出现过的全部自由文本发行方（测试或脚本即可），方便发现「腾讯」与「腾讯游戏」并存；本期不自动改名，只在说明书里要求新数据沿用已有写法

`verified` 仍是整条条目一级，不改成按字段。
