# 发现协议（2026-10-15 用户指令沉淀：渠道要更宽、mapping 要更严谨）

> 背景：用户陆续零碎提示的信息（扶摇一梦、时尚百货城、甄嬛传小游戏、叮当离职信息量）多次命中档案缺口。用户要求：反思为什么没找到，建立更宽的搜索渠道与更严谨的 mapping 方式，并沉淀为长期机制。

## 一、漏收复盘（根因分析）

| 漏收 | 直接原因 | 根因类别 |
|---|---|---|
| 扶摇一梦（萤火首款产品） | 一次关键词检索失败即下"无上线产品"结论 | **负面结论纪律缺失**（已修：≥2种检索公式+官方渠道核验） |
| 爱的番茄全系（我本千金/我的花园世界/时尚百货城） | mapping 只从"已知公司"出发，公司不在清单上就永远看不见 | **单循环 mapping：只有公司→产品，没有渠道→产品→公司** |
| 梦回甄嬛传 | 小游戏渠道不在渠道矩阵里，榜单从不扫描 | **渠道盲区** |
| 浪漫餐厅/柠檬微趣 | 同上；休闲合并品类从未做过品类榜扫描 | **渠道盲区+品类盲区** |
| 璇子执明网络 | 人物离职→新公司→商标注册的链路没有常设跟踪 | **人物事件链跟踪缺失** |
| 叮当再创业信息滞后 | 线索在档但没人推动核实时效 | **新鲜度轮缺失**（校准轮已补，需常态化） |
| 吴杰职务险些错录 | 搜索摘要把"市场VP"混成"制作人" | **摘要≠事实**（已守：角色/数字必须开原文） |

**一句话总结**：此前的 mapping 是"公司驱动"的单循环——认识的公司才会被深挖；而市场是"渠道驱动"的，新品类、新渠道（小游戏）、新公司（爱的番茄）从侧面生长，单循环结构性看不见它们。

## 二、双循环 mapping（新规则）

- **循环A（已有）公司→产品**：公司档案、财报、官网目录、招聘页。
- **循环B（新增）渠道→产品→公司**：从榜单/品类/社区反向发现产品，产品归属不明时反查开发者→补建公司实体。**每个卷每季度至少跑一轮循环B**；发现的新公司当日进 mapping-plan（仅列名即可，不得因为"不认识"而不登记）。
- 两循环交汇验证：循环B发现的厂商，进循环A深挖其全产品线（爱的番茄案例：从1款榜单产品挖出3款女向产品线）。

## 四、负面结论纪律 v2（扶摇一梦教训扩展）

对公司或产品下"无/不存在/查无"类结论前，必须完成：
1. ≥2 种检索公式（不同关键词组合、不同引擎：sogou → 内置WebSearch → bing 轮换，不单点依赖搜狗，反爬时立即换通道）
2. **商店开发者账号反查**（iTunes search 按 developer/seller、应用宝开发者页）
3. 榜单核查（该品类近三月月榜）
4. 结论里记录已用公式与通道，未做完四步不得写 not-found

- **事件驱动**：人物离职/新公司 → 工商+商标+招聘三连查（执明网络模式）；IP官宣（如甄嬛传三款乱战）→ 全竞品登记。
